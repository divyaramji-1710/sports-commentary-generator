# Sports Commentary Generator

[![Built with askThili](https://ask.thili.ai/api/v1/public/projects/huhdbksy6b/badge.svg)](https://ask.thili.ai/b/huhdbksy6b)

A local Streamlit app that uses a LoRA-adapted distilgpt2 model to
generate short commentary for simulated football events.

The adapter is implemented directly in PyTorch without PEFT.
The app merges the adapter into the base weights when loading.

- [x] Create simulated event/commentary pairs.

## Setup

Requires Python 3.12. Run commands from the project root.

### Windows PowerShell

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app/main.py
```

### Linux or macOS

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app/main.py
```

Open the local URL printed by Streamlit.

The base model and tokenizer download from Hugging Face on first use.
No paid API, API key, or GPU is required. Internet access is needed
for the initial download; cached files can be reused afterward.

Direct dependencies are pinned in requirements.txt.

## Using the app

Choose Goal, Save, or Full-time, then edit the event description
and click Generate commentary.

Supported example:

```text
Football. Minute 72. Goal for City. Score after goal: City 2-1 Rovers.
```

Observed output:

```text
City score! That makes it City 2-1 Rovers.
```

Save example:

```text
Football. Minute 35. Save by Eagles. Score unchanged: Eagles 0-0 United.
```

Observed output:

```text
Eagles make the save! It remains Eagles 0-0 United.
```

Full-time example:

```text
Football. Full-time. Final score: Wolves 1-2 Falcons.
```

Observed output:

```text
The match is over! Wolves 1-2 Falcons.
```

Generation uses greedy decoding. Changing the maximum new tokens
sets an upper bound on continuation length, not an exact length.

## Dataset and provenance

The dataset is synthetic and generated by app/data.py with seed 17.

It contains fictional teams, simulated scores, and authored commentary
templates. No real match reports or external commentary corpus are used.

| Split | Examples |
| --- | --- |
| Training | 360 |
| Validation | 60 |
| Test | 60 |

Each split includes goals, saves, and full-time events.
Exact event descriptions do not overlap across splits.

Teams and commentary templates are shared across splits. The evaluation
therefore tests new event combinations within a controlled format,
not unfamiliar sports, team names, or writing styles.

Files:

- data/train.jsonl
- data/validation.jsonl
- data/test.jsonl

Regenerate the dataset:

```powershell
.\.venv\Scripts\python.exe -c "from app.core import milestone_1; milestone_1()"
```

## Model and training

Base model: distilgpt2.

LoRA targets the fused Q/K/V projection, c_attn, in all six
transformer blocks.

- Rank: 8
- Alpha: 16
- Adapter dropout: 0.05
- Trainable parameters: 147,456
- Optimizer: AdamW
- Learning rate: 0.001
- Batch size: 8
- Epochs: 6
- Training steps: 270
- Maximum training sequence length: 64 tokens
- Seed: 17

The pretrained base remains frozen. Training loss is applied only to
commentary tokens and the end-of-sequence token. Event prompts and
padding are masked with -100.

No vocabulary tokens are added. The checkpoint contains the adapter
matrices, base-model identifier, and adapter configuration.

## Training results

Validation loss is averaged over supervised next-token targets.

| Step | Validation loss |
| --- | --- |
| 0 | 3.1500 |
| 45 | 0.5135 |
| 90 | 0.2316 |
| 135 | 0.1369 |
| 180 | 0.1362 |
| 225 | 0.1177 |
| 270 | 0.0976 |

Step 0 represents the unadapted base because B starts at zero.
The lowest-validation-loss adapter was saved at step 270.

Checkpoint: artifacts/commentary/adapter.pt

Training report: artifacts/commentary/training.json

To train a fresh adapter in a separate folder:

```powershell
.\.venv\Scripts\python.exe -u -c "from app.core import milestone_2; milestone_2(output_dir='artifacts/reproduction', epochs=6)"
```

Exact numerical results may vary across platforms and library builds.

## Held-out evaluation

Both models used greedy decoding with a maximum of 48 new tokens
on the same 60 held-out test events.

| Rule-based check | Base model | LoRA-adapted |
| --- | --- | --- |
| Correct score and team order | 0/60 | 60/60 |
| Correct event and acting team | 0/60 | 60/60 |
| Both checks | 0/60 | 60/60 |
| Matches a valid authored template | 0/60 | 60/60 |

The base comparison disables the adapter by zeroing B in a temporary
in-memory model. It does not modify the saved checkpoint.

Full outputs and checks: artifacts/evaluation.json

Rerun evaluation:

```powershell
.\.venv\Scripts\python.exe -u -c "from app.core import milestone_4; milestone_4()"
```

These checks are deliberately narrow. Template matching is not a
general assessment of fluency, creativity, or factual reliability.
A deterministic template renderer would also be a strong baseline for
this synthetic task; it has not been benchmarked separately.

## Adapter merging

The application loads the adapter, merges its update into each frozen
projection, and caches the merged model for subsequent requests.

Verification on three validation examples found:

- Six LoRA wrappers before merging; zero afterward.
- Identical generated continuations.
- Maximum observed logit difference of approximately 0.000206,
  within the configured floating-point tolerance.

Report: artifacts/merge-check.json

Rerun verification:

```powershell
.\.venv\Scripts\python.exe -u -c "from app.core import milestone_5; milestone_5()"
```

The saved adapter stays unchanged. Merging removes the adapter's extra
matrix operations, but this project does not claim a measured latency
improvement.

## Limitations

The model was adapted to a small template-generated dataset.
Its strong test results do not establish general sports understanding.

Unseen teams, free-form event descriptions, different sports, and
events outside the three supported types may produce incorrect output.
The templates provide limited stylistic variety.

The automated checks do not comprehensively detect extra invented facts,
contradictions, or poor writing. Human review remains useful.
